# Decision log

Format: **ID · decision** — context, alternatives considered, consequences.

**D-027 · Replay uses saved locators directly instead of re-detecting.** Context: Milestone B schema replay previously re-ran detector pattern detection (`detectPatterns`), which violated the requirement for deterministic replay using saved locators. Decision: Implemented `L.schema.buildSchemaFromResult` to extract and persist `container`, `item` locators, and `fields` array during schema creation. Replay (`L.schema.run`) now resolves locators directly against the page snapshot, checks signature match, applies field transforms, and calculates health per spec §8 (required fields, locator strategy tier, item count drift >20%). Consequences: Replay is 100% deterministic and independent of detector heuristics.

**D-028 · Glob path pattern escaping & input sanitization.** Context: `matchSchemaUrl` built dynamic Regular Expressions from stored schema `pathPattern` strings without escaping special regex characters. Decision: Implemented custom glob-to-RegExp converter (`globToRegExp`) that safely escapes all metacharacters while supporting `*` and `:param` wildcards, with strict 200-character caps. Consequences: Protects URL matching against ReDoS and hostile string evaluation.

**D-001 · Single standard Chrome extension, no monorepo.** Context: a solo builder gains nothing from `core`/`extension` packages while the engine has one consumer. Alternatives: pnpm workspace with a publishable core (earlier plan). Consequence: simpler repo, load-unpacked works; reusability is preserved by layering rules (engine files never touch `chrome.*` except overlay/bridge), so a future split is mechanical.

**D-002 · Engine as classic scripts in numbered layers, injected on demand.** Alternatives: ES modules (needs `web_accessible_resources`, exposing extension files to every site); a bundler (adds a build step and tooling). Consequence: no build, no exposure; files share one namespace, so layering discipline and a unit-tested file list are required.

**D-003 · No `content_scripts`, no required host permissions; `activeTab` + `scripting` only.** *Superseded by D-018 on host access; the no-content-scripts decision remains.* Alternatives: `<all_urls>` content scripts for automatic stage-0 on every page. Consequence: strongest privacy/review story; automatic per-site suggestions on revisit become an opt-in per-site host permission in Phase 1.

**D-004 · Plain JavaScript, no framework, no TypeScript in Phase 0.** Alternatives: TypeScript + bundler; Preact/Svelte panel. Consequence: zero tooling and fast iteration. Revisit at Phase 2 if the panel's complexity (DOM map, field editor) justifies a framework; any change must keep the `src/` layout loadable unpacked.

**D-005 · Scored candidates with transparent evidence, per-kind thresholds (article .45, table .45, record list .50).** Alternatives: fixed per-detector confidences; ML classifier. Consequence: explainable ("why this score" in the Map), tunable via fixtures. Thresholds are uncalibrated and labelled as such.

**D-006 · Listing pages are penalised as articles ("repetition" signal).** Found by the blog-index fixture: a list of posts looked like long prose. Alternative: hard-reject any container containing a record group. Chosen: −.40 weight when ≥70% of the container's text is a repeated item list with headings/links, so real articles with bullet lists are unaffected.

**D-007 · Tiny record groups need real content.** Three feature cards on a landing page scored as a listing. Rule: groups of 3 require link/image presence ≥60% and avg item text ≥40 chars.

**D-008 · First visit still offers a universal extractor ("Quick extract").** Superseded by D-013: the default first visit now offers Inspect, not a page-wide scan. Kept as the Phase 0 baseline record.

**D-009 · Jsdom for Phase 0 tests; real-browser harness in Phase 1.** Jsdom lacks layout, so no layout/perf claims are made from it. The side panel's runtime behaviour was not exercised in Chrome in this delivery; the smoke checklist is the Phase 0 gate.

**D-010 · Open-core intent (MIT engine) and name "Lasso" are working assumptions.** Check Web Store/trademark/domain availability and confirm licensing before the public beta.

**D-011 · Site profile stored per hostname in `chrome.storage.local` (background only, capped at 500).** Alternative: IndexedDB. Consequence: simple and sufficient for Phase 0; schemas may move to IndexedDB later.

**D-012 · Phase 0 real-browser smoke harness with Playwright.** Context: jsdom cannot exercise the side panel, chrome.* messaging, overlay geometry or a real extraction flow. Alternatives: manual-only smoke test; Puppeteer. Consequence: `test/e2e.mjs` launches Chromium with the unpacked extension and serves the fixture corpus on `127.0.0.1`; the shipped `http(s)` host access now covers the fixture server, so the old temporary manifest rewrite is no longer needed. The harness is currently paused: it still assumes the Phase 0 auto-detect UI and must be rewritten for the inspect-first flow. It is not part of `npm test`.

**D-015 · Inspect defaults: custom overlay menu, left-click/right-click selection, four core patterns.** Owner approved the recommended defaults, 2026-10-26. Context: native `contextMenus` would add a permission and cannot carry per-node evidence; a fixed pattern set keeps the first milestone testable. Alternatives: native menu; right-click-only selection; add Links/Images/Code now. Consequence: right-click opens a custom ARIA menu in the closed shadow root; left-click selects, right-click selects + opens the menu. *Superseded by D-021: the pattern picker now shows inline checkboxes (Text default) and a single Detect selected action; there is no separate Detect-then-list step.* Map checkboxes are the keyboard/touch equivalent; Article/Table/List/Text are the core set. Chat/Contact were later added as preview extensions under D-017. Field-level picking and further patterns wait for evidence. `Quick extract`/Edit mode stay out of the default UI. Session state is per-tab (D-014).

**D-014 · Inspect mode is per-tab state, with local session stats.** Owner direction, 2026-10-26. Context: a global toggle would either leak inspect mode onto every tab or silently kill the previous page’s session on a tab switch. Alternatives: global mode (simple, wrong mental model); exit on tab switch and re-enter manually (loses a configured selection). Consequence: the content script owns the session (snapshot, selection, result, counters) and the panel queries `INSPECT_STATE` for the active tab on every switch. Switching away does not stop the previous tab; navigation/reload/tab close ends it. Stats are ephemeral, local and per-tab.

**D-013 · Inspect-first replaces auto-detect-first as the target UX.** Owner direction, 2026-10-26. Context: page-wide detection guesses what the user wants, costs a full scan on the first interaction and narrows “any part of a page” to three shapes. Alternatives: keep Quick extract as the primary path and add click-to-pick later (the old Phase 2 plan); keep auto-detect as a fallback. Consequence: the default UI stops scanning; Inspect activates a DevTools-like picker and a live DOM tree; the user chooses one or more patterns from a checkbox picker and clicks Detect selected (D-021); Output becomes the configure/save surface; saved recipes replay with one click. The locator/schema work (old Phase 1) moves onto the critical path; the Phase 0 auto-detect UI is the baseline, not the destination. Open sub-decisions (menu implementation, exact gesture, MVP pattern set, revisit auto-run) are listed in `docs/VISION.md` §16; the Milestone A defaults were confirmed in D-015.

**D-016 · Optional per-origin access recovers a lost `activeTab` grant.** *Superseded by D-018; retained as the rejected alternative.* Context: after an extension reload, Chrome drops the transient `activeTab` permission held by the already-open panel; engine injection then fails with a permission error, which made Inspect appear broken until the user re-clicked the toolbar icon. Alternatives: required all-site host permissions (silent, but an excessive install-time grant and a store-review liability); require a toolbar re-click (simple, but not the “smooth and implicit” experience the owner asked for); no recovery (unacceptable). Chosen: declare `http://*/*` and `https://*/*` as **optional** host permissions; on a permission error the panel requests only the current origin, retries once, and also offers a direct “Enable on this page” button. Consequence: Chrome may show one native prompt per origin after a reload; the direct button is the gesture-safe path. The requested pattern omits ports because Chrome match patterns do not support them. This is the minimum privilege that preserves recovery without install-time all-site access.

**D-017 · Inspect patterns are a registry; Chat and Contact are preview extensions.** Context: hard-coding a switch in `35-inspect.js` would make each new pattern a core edit, and the owner wants to integrate more detection patterns over time. Chosen: `L.inspect.registerPattern({id,label,order,detect,build})` with built-ins registered in `35-inspect.js`; Chat (`36-pattern-chat.js`) and Contact (`37-pattern-contact.js`) register through the same API. Layers 36–37 may use 0–35. Alternatives: a config-only table with no builders (too rigid for different data shapes); separate page-wide detectors (conflicts with inspect-first). Consequence: a pattern supplies applicability (`detect`) and output shape (`build`); adding a new output kind also needs `60-output.js` support and fixtures. Chat role detection and Contact extraction are heuristics, not per-site adapters; neither is claimed as calibrated. The registry is inspect-only; the legacy detector registry remains for fixtures.

**D-019 · CSV export is formula-safe by default.** Context: spreadsheet apps execute cells beginning with `=`, `@`, and some `+`/`-` expressions; scraped page text is untrusted. Chosen: prefix a single quote when a cell starts with `=`, `@`, tab, CR, a `+`/`-` expression or a non-numeric signed value; keep ordinary negative numbers and `+` phone numbers unchanged. Alternative: an opt-in checkbox (safer data fidelity, unsafe default). Consequence: some spreadsheets show the protective apostrophe; the exported text stays inert. The panel still adds the optional UTF-8 BOM.

**D-020 · Pattern detection is explicitly gated by a Detect action.** Owner direction, 2026-10-27. *Superseded by D-021; retained as the history of the first gate.* Context: merely selecting an element (or restoring a tab) was still probing every pattern and showing the result list, which was detection before the user asked for it. Chosen: selection stores only the node; the overlay menu first showed **Detect**, the Map showed **Detect patterns**, and either action ran `L.inspect.detectPatterns(nodeId)` once against that selection and cached the results. No page-wide scan, no probing on selection/restore/page load. Consequence: one extra click before the pattern list; `INSPECT_PATTERNS` means “run detection”.

**D-021 · Checkbox pattern picker, Text default, single-result Send and multi-result Output cards.** Owner direction, 2026-10-27. Context: the explicit Detect gate still made the user detect all patterns before choosing, and a multi-pattern result had no single readable surface. Chosen: selection still stores only the node. The overlay and Map show inline checkboxes for the pattern catalog; **Text** is checked by default; checking another pattern auto-unchecks Text, and rechecking Text explicitly creates a multi-pattern selection. **Detect selected** runs only the checked patterns against that selection. One selected pattern shows a result-description view with an explicit **Send to Output**; multiple selected patterns go directly to Output as one collapsed, expandable card per pattern (failed patterns show an error card). No automatic output for a single result; no page-wide scan. `INSPECT_PATTERNS {nodeId, patterns}` now carries the selection; `INSPECT_RENDER_ALL` renders the card set. Consequence: the user controls cost and scope before detection; Text remains the safe one-click default; the old Detect-then-list flow is gone.

**D-022 · The panel paints from a structural key; hover updates rows in place; inspect gestures are blocked unconditionally.** Context: every `set()` rebuilt all three views with `replaceChildren`, and hover sync fires on each new element under the pointer, so sweeping the mouse rebuilt the whole DOM tree per element; separately, the gesture guard only blocked when the event target resolved to a snapshot node, so on a truncated document the page could still navigate under the picker, and press-release events (`mouseup`, `auxclick`, `pointercancel`) were never blocked. Alternatives: virtualise the tree (right answer at much larger scale, unnecessary now); per-view diffing helpers (more machinery than the problem needs); keep per-event full renders and only throttle (throttling a full rebuild still stutters). Chosen: `panel.js` computes a structural key of everything the views read *except* `hoverId`; an unchanged key re-applies hover classes to the existing rows, hover is coalesced to one paint per frame, and every other state change paints synchronously. The overlay blocks its gesture list on any target outside the host, snapshot node or not. Consequence: a stale key silently drops a repaint, so anything a view reads must be added to `structuralKey()` — the panel smoke asserts that a hover update leaves the rendered rows connected, and the browser smoke tags a row and asserts the tag survives a hover.

**D-023 · Retire the legacy message surface, region overlay and single-pattern apply.** Context: after the inspect-first pivot, `ANALYZE`, `RENDER`, `FORMATS`, `SELECT`, `OVERLAY`, `DESTROY`, `INSPECT_APPLY` and the page→panel `REGION_CLICKED`/`PATTERN_APPLIED` messages had **no caller anywhere in `src/`**, and `test/e2e.mjs` (the harness the docs said they were retained for) contains no reference to any of them and is not wired to a script. The overlay's whole region-box mode (colours, chips, `show`/`select`/`clear`) existed only to serve those messages; `L.inspect.patternsFor()` probed every registered pattern on demand, which is exactly the eager detection D-020/D-021 removed, and `panel.js#applyPattern` was unreachable from every view. Alternatives: keep them "for the paused harness" (the status quo, which is how the rot the review predicted had already set in); keep only `ANALYZE` as a benchmark entry (the harness calls `L.analyze()` directly, so a message wrapper buys nothing). Chosen: delete the message handlers, the region overlay mode and its CSS/exports, `panel.js#applyPattern`, `state.js#flatten`, `L.inspect.apply/patternsFor/lastResults`, and migrate the unit tests to `detectPatterns`, the shipped entry point. The Phase 0 pipeline (`L.analyze`, detectors, arbitration, classification, `L.output.render`) stays: the inspect patterns share `L.segment`, `L.articleHints`, `L.extractTable` and `L.textOf`, and the fixture harness is the pipeline's only consumer. Consequence: the "applied" stat is now incremented by `detectPatterns` (it was previously only incremented by the removed `apply`); `test/e2e.mjs` is documented as stale and unwired rather than deleted (no VCS in this working copy).

**D-024 · Visibility via `Element.checkVisibility()`, with the 25k snapshot budget deferred to a chunked walk.** Context: the first real measurement (`npm run perf`, from D-023's harness) showed the snapshot as the single dominant main-thread task — 25k p50 ~467 ms — because it materialises a full computed style per element just to read four properties, and `MASTER_SPEC` §12's "no task >50 ms at 25,000" was missed by an order of magnitude. Alternatives: (a) slice the snapshot by turning the recursive walk into a chunked async worklist — the only way to actually meet the budget, but `L.snapshot` is called synchronously by the detectors, the formatters, article hints, three patterns and every unit test, so an async API ripples through the whole engine and its tests immediately before a release; (b) lower the 25k node cap to bound the block — moves the goalposts, contradicts the documented cap, and still misses 50 ms; (c) leave it and only document the miss. Chosen for now: (a) is deferred, and the cheap half is taken — `Element.checkVisibility({checkOpacity, checkVisibilityCSS, contentVisibilityAuto})` replaces `getComputedStyle` for the common visible case in Chromium, with computed style kept as the fallback (jsdom has no `checkVisibility`) and as the disambiguator between "subtree gone" and "own text hidden, visible descendant follows". Measured: 25k snapshot p50 ~467 → ~383 ms (repeatable, tight ranges); the 5k p95 ranges overlap (99–106 → 77–100 ms) so that gain is suggestive only on this noisy 4-CPU container. Behaviour is unchanged (41 unit tests, panel smoke, 11/11 fixtures and 15/15 browser scenarios stay green). Consequence: the 25k budget is **still missed** (~433–616 ms unbroken), so Milestone B opens with an async/chunked snapshot or the budget must be restated; `npm run perf -- --strict` is the gate that keeps this honest.

**D-025 · Selected-scope output fidelity: raw pre text, nested lists, scoped article hints, dialog roots and visible-only contact.** Context: review probes found six extraction defects that the fixture corpus did not cover: `<pre>` newlines were collapsed by the snapshot and produced one-line code fences; nested `<ul>` items were flattened into their parent bullet; adjacent link cards glued into invalid `[a](x)[b](y)` Markdown; an inspect selection of a comments block inherited the page-wide `<h1>`/byline as its article title; a selection inside `role=dialog` rendered nothing because the dialog's inherited `bp` (0.85) suppressed the root; and Contact read live `textContent`/`querySelectorAll`, leaking `display:none` and `aria-hidden` emails, addresses and links. Alternatives: add per-site adapters (premature), raise the boilerplate threshold (would leak real cookie/nav content), or treat the whole selected subtree as trusted and keep nested boilerplate (contradicts the extraction contract). Chosen: keep original text-node whitespace in a parallel `rawParts` list for `<pre>` subtrees and add `rawTextOf`; render list items as multi-line blocks with preserved indentation; insert a space between adjacent anchor pieces; add `scoped: true` to article hints so the inspect path never falls back to page-wide H1/byline/metadata; render a user-selected high-`bp` root while still dropping descendants whose *own* `bpOwn` is boilerplate; and walk the snapshot (not the live DOM) in Contact with `skipAriaHidden`. Consequence: page-wide hints keep their metadata fallbacks, so all 11 fixtures still pass; six new unit checks pin the defects; the 25k perf profile is unchanged except for the small `rawParts` allocation inside `<pre>` subtrees.

**D-026 · Output actions are explicit again; the inspect smoke drives stable state.** Context: `MASTER_SPEC` and the README promised **Copy** and **Download** in Output, but the single-result and multi-card views never rendered those buttons (the panel actions existed, unused), so the browser smoke timed out waiting for a Download that did not exist. Separately, the smoke clicked pattern labels that the panel re-renders after every pick, queried the Send gate before the detection response painted, waited on a `display:none` textarea, and let a panel reload steal the last-focused window; those were harness races, not extraction failures. Chosen: render Copy/Download on the single Output view and on each expanded multi card; in the smoke, drive checkboxes by their stable `value`, wait for either the single result card or the Output view after Detect, read the visible `.out-pre`, and re-focus the fixture tab after a panel reload. Alternative: keep Export as the only Output action and weaken the smoke (rejected — it would hide a missing UI). Consequence: Copy/Download now match the spec, and the headless inspect smoke runs the visible surface deterministically; the native-Chrome manual gate is still required.
